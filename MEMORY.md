## Граблі (на які вже наступали — не повторювати)
- PowerShell `@'…'@` у Bash-інструменті ламає повідомлення коміта (див. CLAUDE.md, розділ «Коміти»).
- `python3` у Windows — заглушка Microsoft Store, а не Python. Скрипти викликати через `python`.
- Консоль Windows у cp1251: Python падає з `UnicodeEncodeError` на символах типу `→`. Ліки — `PYTHONUTF8=1`
  (прописано в `.claude/settings.json`; у вже запущеній сесії — `export PYTHONUTF8=1` перед командою).
- Node ESM: `new URL(import.meta.url).pathname` на Windows дає `/C:/...` → «MODULE_NOT_FOUND». Тільки `fileURLToPath`.
- Скіли/скрипти «для macOS і Linux» (ref2game) перед використанням проганяти на тестовому проєкті в scratchpad.
- Встановлення з правами адміністратора (winget/MSI) при віддаленій роботі з телефону зависає на вікні UAC,
  яке нікому натиснути. Ставити портативні версії в `C:\Soft\` (так поставлено `C:\Soft\cloudflared\cloudflared.exe`).
- `trycloudflare.com` (швидкі тунелі cloudflared) з цієї мережі недоступний — таймаут, хоча cloudflare.com відкривається.
  Вхідні тунелі (localhost.run тощо) Claude Code у режимі auto блокує — лише з явного дозволу користувача.
  Користувач дозволив localhost.run (2026-10-15), перевірено — працює: `ssh -o StrictHostKeyChecking=accept-new
  -R 80:127.0.0.1:<порт> nokey@localhost.run` (у фоні, URL `https://<id>.lhr.life` — з логу). Адреса щоразу нова
  і без акаунта змінюється сама вже за лічені хвилини (стара видає «no tunnel») — перед тим як давати
  посилання, брати найсвіжішу `*.lhr.life` з кінця логу. Довша адреса — акаунт localhost.run + SSH-ключ.
  Після сесії тунель вимикати: зупинка фонової задачі НЕ вбиває `ssh.exe` — добивати `taskkill //PID <pid> //F`
  (перевірити `tasklist //FI "IMAGENAME eq ssh.exe"`). Вузли Cloudflare :7844 доступні —
  іменований тунель cloudflared запрацює, якщо з'явиться свій домен на Cloudflare.
  Тунель сам обривається (фонова задача завершується з кодом -1) — перезапускати; лог тримати в проєкті
  (`experiments/<гра>/frames/tunnel.log`), бо scratchpad може зникнути між вікнами контексту.
- Тунель localhost.run тягне ~34 КБ/с: PNG-фон 3 МБ вантажиться ~95 с. Великі непрозорі фони — JPEG, дрібні UI-спрайти —
  PNG з палітрою (`tools/web.py`), а мітка кешу картинок — відбиток `assets.js`, не `Date.now()` (інакше кожне живе
  оновлення сторінки заново качає мегабайти).
- Claude Code сам гасить фонові задачі, коли бракує пам'яті (сервер сторінки впав при ~1 ГБ вільних з 16; Android Studio
  їсть ~2 ГБ). Без дозволу користувача такі задачі не перезапускати; перед запуском перевірити вільну пам'ять.
- Scratchpad (`%TEMP%\claude\...`) може зникнути між вікнами контексту — скрипти й логи, що ще знадобляться, класти в проєкт.
- Довгі Python-патчі в heredoc Bash-інструмента ламаються на лапках («unexpected EOF») — писати скрипт файлом і запускати.
- Чекати фонову задачу через `sleep N` заборонено — `timeout 240 bash -c 'until <умова>; do sleep 3; done'`.

### Граблі ref2game / рушій
- `prep.py` обрізає прозорі краї кожної текстури — частини маріонетки на спільному полотні тоді «роз'їжджаються».
  Частини (`*__*`), шари рук (`*_arms`), ваги (`*_w`) — у `prep.notrim` в `ref2game.json`.
- `live/index.html` вантажить ФІКСОВАНИЙ список скриптів: новий файл (`story.js`, `rigs.js`, `puppet.js`) додавати і в
  список завантаження, і в WATCH (живе оновлення).
- `qa.mjs` читає камеру зі стану як масив `cam: [x, y]`; число в `cam` дає NaN і тихо ламає перевірку ковзання ступнів.
  Камера-число — під іншим ім'ям (`camX`).
- `qa.mjs` вважає кожен `L.label` текстом інтерфейсу («вилазить за екран», «перекривається»). Таблички й підписи
  в кімнаті малювати текстурою мітки напряму (`sign()` у `scene.js`), без реєстрації в QA.
- `L.labelW` і `L.label` з одним слотом мусять мати ОДНАКОВІ опції (колір, обвідка): ключ кешу містить їх, інакше текстура
  перемальовується щокадру.
- `gen.py` завжди додає біблію стилю. Для асетів в іншому стилі (олівцеві піктограми) — `tools/gen_raw.py` (плагін напряму).
  Коли міняєш гаму запитом, рядок палітри з біблії суперечить запиту — прибирати (випадок еталону v4).

### Граблі генерації (Meshy, gpt-image-2)
- Стара «ШІ-гладка» картинка в референсах повертає ШІ-дрібноту в нову — для стилю давати лише затверджений еталон.
- Ширше 16:9 Meshy не малює: панораму робити двома половинами, праву — з лівою як референсом; шов ховати у вертикальний
  предмет на обох (труба), виміряти його стовпці й зшити (`tools/stitch.py`), підлогу змішувати широкою смугою.
- Аркуші піктограм: близькі по вертикалі іконки зливаються в одну компоненту (знак питання + крісло) — різати сіткою по
  найпорожніших рядках кожного стовпця (`tools/ui_sprites.py`).
- Персонажі: `rigcut.py` на довгому халаті відрізає рюкзак як «руку», а поділ — разом із ногою → брати аркуш частин.
  Одна рука/нога на обидва боки в ракурсі 3/4 виглядає фальшиво → окремі ліві/праві (`tools/rig_lr.py`).
- Руки-«палички» з аркуша частин або лежать на тілі як наліпки, або ховаються так, що стирчить один манжет; програмне
  домальовування під рукою дає смуги. Що працює: Meshy-редагування якоря «той самий малюнок без рук» (майже піксель
  у піксель) як тіло + руки з якоря окремим шаром на «м'яких кістках» (`tools/split_arms.py`, `art/softbones.json`).
- М'які кістки годяться лише для малих махів (±0.3 рад): на 1.5+ рад (замах над головою, рука до рота) рука тягнеться
  «локшиною». Для жестів — жорсткі шматки з якоря (плече + передпліччя, круглі «кулі» суглобів), `tools/make_top.py`.
- Корінь кістки/суглоба має бути ВСЕРЕДИНІ силуету: координати знімати з самої текстури верху (`tools/grid.py`),
  а не перераховувати з якоря на око — промах на 20–30 px дає «шапку» суглоба з порожнечі.
- Довгий плащ у маріонетці нерухомий: сидячу позу він не передає — для сидіння окремий малюнок (Мирон на кріслі).
- Хода: ноги на якорі стоять широко; без зведення до центру (puppet.js `nar`) зсув лишається в ході → «приставний крок».
- Штани між полами у верху мають бути ПРИБРАНІ (`make_top.py --belt`) — інакше стегна нерухомі й видно розрив з ногами.
- У ракурсі 3/4 ближня рука з якоря — вузька смужка; для жестів показувати повну руку з аркуша (`armBlend`).
- `make_top.py` переписує `art/src/NAME_top_orig.png` і обрізає по порогу прозорості 60 — для Ліни (старий верх) не запускати.
- Камера: `camX` не більше ніж ширина кімнати мінус 1920 (≈1668), інакше кадр праворуч чорний (у `tools/snap.mjs`).
