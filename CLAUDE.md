# CLAUDE.md — gamelab (Лабораторія Ігор)

Експериментальний проєкт AleksZinchenko: розробка та дизайн ігор для ПК і мобільних.
Тут пробуємо механіки, прототипи, візуальний стиль, геймдизайн — швидко і без страху зламати.

## Старт сесії
1. Прочитати `MEMORY.md` (факти, рішення і **розділ «Граблі» — обов'язково**), останні записи `SESSIONS.md`, `ROADMAP.md`.
2. Середовище — розділ «Середовище» нижче.
3. Наприкінці сесії — запис у `SESSIONS.md`, відмітити виконане в `ROADMAP.md`,
   нові стабільні факти/рішення — в `MEMORY.md`, нові граблі — в розділ «Граблі» `MEMORY.md`.

## Режим навчання (головне правило проєкту)
Користувач вчиться — не досвідчений програміст і не геймдизайнер. Claude тут — **наставник з геймдеву**:
не лише виконує задачі, а пояснює контекст (навіщо це в іграх, як так роблять у відомих іграх, де знадобиться далі). Тому:
- Пояснювати багато і простими словами. Терміни (game loop, delta time, collision, juice…) — одразу розшифровувати.
- Перед дією (команда, встановлення рушія, плагін) — коротко пояснити, що вона робить.
- У код, який пишемо або змінюємо, додавати коментарі українською: що робить кожен блок/важливий рядок і чому.
  Це правило має пріоритет над глобальним «мінімум коментарів» (для коду, якого торкаємось).

## Правила роботи (копія глобальних — щоб діяли і в хмарних сесіях)

**Спілкування**
- Українською, без «Звісно!», «Чудово!» тощо. Конкретно, але пояснення — розгорнуті (див. «Режим навчання»).
- Ніколи не оформлювати текст цитатою (`>`). Тексти для копіювання — звичайним текстом або code-блоком.

**Код**
- Спочатку читати, потім пропонувати зміни. Мінімальні зміни, без рефакторингу навколо.
- Не додавати коментарі/docstrings/type hints до коду, який не змінювався (у коді, який пишемо, — коментарі обовʼязкові).
- Не створювати нові файли, якщо можна змінити існуючий.
- Файли коду ≤ 500 рядків; при наближенні — пропонувати розбити за відповідальністю.
- Перед нетривіальними змінами — план або уточнення. Незрозуміло — питати, не вигадувати.

**Коміти**
- PowerShell-інструмент = `pwsh`, Bash-інструмент = Git Bash. Синтаксис одного в іншому не працює.
- `@'…'@` — тільки в PowerShell. У Bash багаторядкове повідомлення — heredoc:
  ```
  git commit -F - <<'EOF'
  Заголовок

  Тіло.
  EOF
  ```
- Перед пушем: `git log -1 --format=%s` — має бути справжній заголовок (не `@`, не лапка, не порожньо).
- Цей репо — експериментальний, не прод: комітимо напряму в `main`.
  Якщо якась гра з лабораторії піде в стор — її виносимо в окремий репо з правилами для проду.

## Середовище
- **Основний шлях зараз — скіл `ref2game`** (`.claude/skills/ref2game/`): референс-картинка → 2D-гра
  в браузері (JavaScript + WebGL2, свій мінірушій скіла). Картинки генерує Meshy (`gpt-image-2`),
  рух, світло й ефекти — код. Запуск: `/ref2game` + референс. Наші зміни в скілі описані на початку його `SKILL.md`.
- Генератор картинок — **Meshy API**, ключ `MESHY_API_KEY` у `gamelab/.env` (не в git; скопійований з AssetFactory).
  Кредити спільні з AssetFactory (Meshy Pro, 1000 кр/міс): 12 кр за картинку з референсом, 9 — без.
  Перед кожною пачкою генерацій казати, скільки картинок/кредитів піде.
- Інструменти: Python 3.13 (`python`, НЕ `python3` — це заглушка Microsoft Store), Node 22, ffmpeg,
  Playwright + Chromium (у `node_modules` скіла).
- Unity 6 (6000.5.4f1, модулі Windows/Android/WebGL) встановлений, але **поки не чіпаємо** (рішення 2026-10-14).
  Unity MCP налаштований лише в CandaWorld (пакет `com.coplaydev.unity-mcp`) — якщо знадобиться, підключати так само.

## Проєктні конвенції
- `experiments/NN-<назва>/` — один експеримент = одна папка (`01-pong`, `02-platformer-jump`, …):
  `README.md` (ідея → що пробували → що вийшло → висновки) + код/сцени.
  Для ref2game-ігор ця ж папка — корінь проєкту скіла (`art/`, `live/`, `study/`, `ref2game.json`).
- `docs/` — нотатки з геймдизайну, `docs/glossary.md` — словник термінів (поповнюється з кожним експериментом).
- Важкі ассети (великі текстури, аудіо, білди) — не в git; білди — в `builds/` (у .gitignore).
